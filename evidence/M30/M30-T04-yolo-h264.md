# M30-T04 开启 YOLO 后 H.264 解码错误修复

## 现象

管理后台开启“YOLO 视频分析”后，服务端控制台连续出现：

- `Invalid level prefix`
- `corrupted macroblock`
- `Missing reference picture`
- `decode_slice_header error`

VLC 读取同一 RTSP 地址正常，说明问题位于服务端解码路径，不是管理后台的 `object-fit: contain` 样式。

## 根因

YOLO 安装过程额外安装了 `opencv-python 5.0.0.93`，覆盖了项目要求的 `opencv-python-headless 4.14.0.94`，实际 `cv2.__version__` 为 5.0.0。服务端 OpenCV 拉流也没有显式固定 RTSP TCP。

独立 FFmpeg 9.0.1 使用 TCP 解码同一输入 20 秒无错误；OpenCV 5 在真实 YOLO 负载下则持续报告参考帧和宏块损坏。

## 修复

- RTSP / RTSPS 输入显式使用 OpenCV FFmpeg 后端，并设置 `rtsp_transport;tcp`。
- 新增 `RTSP_TRANSPORT` 配置，默认 `tcp`，仅允许 `tcp` / `udp`。
- `requirements-yolo.txt` 将 `opencv-python` 约束为 `>=4.10,<5`。
- Windows 启动脚本验证实际加载的 OpenCV 主版本；发现 5.x 时自动恢复 4.x。
- 当前虚拟环境已从 OpenCV 5.0.0 降级到 4.14.0。
