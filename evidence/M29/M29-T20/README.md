## 根因与修改

- 详情监听函数每次生成新数组，即使项目/事件ID没有变化，同一事件列表的新对象仍触发初始化：重复证据请求、清空处置备注及AI建议，造成闪动和滚动干扰。
- EvidenceImage存在相同监听方式，轮询后把已加载状态置为false；图片URL未变且不会再次触发load，导致标注消失。
- 改为分别监听打开状态、项目ID、事件ID（证据图另监听src）；同身份新快照只更新事实字段。证据缩略图引用变化单独加载，保留用户选择查看的原图。
- 关闭、切项目或事件仍清理详情和证据。AI历史异步响应绑定视图代数和原请求，防止切换后迟到响应回填。
- 正常5秒REST补拉、WebSocket实时更新、处置权限和原图请求继续保留，没有通过停止同步回避问题。无后端Python或数据库迁移改动。
