# M42-T11 管理员手工托管 APK 的简化版本登记

## 操作与实现

1. 管理员自行构建、使用正式批准证书签名，上传 APK 至 MinIO 或第三方托管空间，取得公开 HTTPS 文件直链。
2. 后台「平台管理 → App 版本管理 → 新建版本」填写版本名称、versionCode、APK 直链、提醒级别、更新说明和审计原因。单一发布范围自动选择，多个范围必须选择；额外重定向域名为高级设置。
3. 「核验 APK」复用现有 external-artifacts 接口和完整 APK 核验作业，不调用 MinIO 上传接口。主机域名自动加入白名单，其余服务端 HTTPS/DNS/重定向和签名校验继续生效。
4. 显示实际版本、大小、SHA-256、证书摘要。版本不匹配时禁止创建草稿，允许修正手填版本。重复字节工件沿用服务端 resolvedArtifactId，不误判原始占位工件失败。
5. 核验通过后，用户明确点击「创建版本草稿」。随后进入原有版本详情，核对来源并「配置并发布」，保留普通/重要/兼容门禁及快速恢复能力。

原「上传 APK」「登记外链」收起至「其他安装包操作」。不新增依赖、不改移动端协议、不改生产配置或业务库。服务端核验需要一次完整 APK 入站流量；设备下载直接访问托管源。

## 失败与生命周期

- 发送中禁止重复提交；同内容网络重试复用幂等键；409/410 锁定当前操作，需关闭刷新后确认。
- 服务端返回 401/403 后立即关闭向导、清空台账及配置，禁止继续提交。
- 核验失败不自动重试新登记，不创建草稿。用户检查 APK/链接后重新登记。
- 关闭窗口/切换账号/离页会中断浏览器请求和定时器，忽略迟到结果；不冒充撤销服务端已接受作业。
- 未提交表单不持久化；已登记工件可从台账继续创建草稿。

## 验证边界

组件测试替换 API，浏览器测试使用真实生产资产但版本 API 为确定性 fixtures，上传回归模拟传输事件。本次验证后台交互，不能作为真实服务/公开托管/正式 APK/Android 覆盖安装的联合验收。M42-T10、M118-T08 保持最后执行，本次不启动。

正式启用仍需现有升级服务身份/批准证书、独立元数据密钥及发布范围、SDK 核验工具、可信构建兼容配置和相关开关。主流程不要求 MinIO 上传凭据或 APK 专用桶；使用公开 MinIO HTTPS 直链时由管理员自行维护托管。现有内部 HTTP MinIO 地址不能直接当作本流程公开 HTTPS 下载地址。未部署生产环境。
