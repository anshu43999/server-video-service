## 完成摘要

推理输出改为结构化检测结果：新增 app/detection.py（NormalizedBox/Detection/InferenceResult/FrameDetections，纯标准库，同时映射协议 §6.2 线上消息与告警引擎 §4 观测信封）、app/overlay.py（叠加只从结构化结果推导），app/detector.py 用 infer() 取代 annotate()，不再产出 results[0].plot() 的已画框图像；叠加按流可关闭（overlay_enabled + PATCH /config + YOLO_OVERLAY），关闭时发布原始帧且检测结果照常产出

## 完成标准

推理返回类别、置信度和归一化坐标的结构化结果，叠加基于该结果实现且可关闭，不再只产出已画框的图像

逐条对应：

| 要求 | 落点 |
|---|---|
| 返回类别 | `Detection.class_id` + `Detection.label`；`resolve_label()` 取权重原始类名，越界或空名退化成 id 字符串，不猜业务名 |
| 返回置信度 | `Detection.confidence`，构造期校验 `[0, 1]`，适配层对越界值夹紧；线上消息保留 4 位、观测信封 6 位 |
| 返回归一化坐标 | `NormalizedBox`：左上原点、`x+w ≤ 1` 与 `y+h ≤ 1` 构造期校验、越界夹紧、退化框（宽或高归一化后为 0）丢弃而不抛错 |
| 叠加基于该结果实现 | `app/overlay.py::draw_overlay()` 只读 `box`/`class_id`/`label`/`track_id`，颜色按 `class_id` 稳定生成；`SourceContractTests` 断言 `app/detector.py` 里已无 `plot()`、无 `def annotate` |
| 叠加可关闭 | `StreamSession.overlay_enabled`（默认 `settings.yolo_overlay`，环境变量 `YOLO_OVERLAY`）+ `PATCH /api/streams/{id}/config {"overlay_enabled": false}`；关闭时发布字节与原始帧编码逐字节相同，检测结果照常产出 |
| 不再只产出已画框的图像 | `infer()` 返回 `InferenceResult`，叠加变成它的下游；`StreamSession.latest_detections` 独立保存一帧结构化结果，供 M08-T05 旁路与 M11-T03 观测接入消费 |
| 一份结构三处消费 | `FrameDetections.to_wire()` 键集与 `docs/video-protocol.md` §6.2 的 JSON 示例逐键相等（测试直接解析文档里的代码块）；`to_observation()` 键集 ⊆ Schema `Observation.properties` 且 ⊇ `required` |
| 能力显式申报 | `derive_provides()`：检测型权重恒申报 `BOX`（空帧也申报，否则 `ABSENCE` 一类规则会被误拒），`TRACK` 只在真的带跟踪 id 时申报；`CAPABILITY_*` 常量与 Schema `Capability` 枚举交叉校验 |
| 代码不含业务类别名 | `SourceContractTests.test_no_business_class_names_in_inference_or_overlay` 对三个源文件做全词匹配（helmet/hardhat/smoke/smoking/fire/flame/phone/vest/intrusion） |
| 真实链路验证 | `models/yolo11n.pt` + ultralytics `bus.jpg`：5 个目标（bus 0.94 + 4×person）、80 个类名、`provides=('BOX',)`、观测信封 8 个键齐全、叠加正常绘制 |

## 遗留问题

- **没有任何任务负责开启跟踪，`provides` 恒为 `["BOX"]`**。`infer()` 走 `model.predict`，不走 `model.track`，`Detection.track_id` 永远是 `None`。数据链路已经铺好（`track_id` 字段、`derive_provides()` 的 `TRACK` 分支、Schema 的 `trackId` 正则、金样向量 `op-presence-track-consecutive-frames` 都在），但缺调用侧，所以告警引擎里以 `track:` 为主体的算子（`PRESENCE` 连续帧、`DWELL`、`LINE_CROSS`）在服务端一律会被 `CAPABILITY_UNSATISFIED` 显式拒绝。**任务板上没有这条任务**，`M11-T05`/`M11-T06` 落地前必须补一条「启用 ByteTrack/BoT-SORT 并申报 TRACK」，否则一致性向量里那几条在服务端永远跑不通。
- **`MASK` 从不申报**。没有分割权重也没有掩膜产出，`CAPABILITY_MASK` 常量只用于与 Schema 枚举对齐的断言。`AREA_RATIO` 在服务端只能走框退化分支（`op-area-ratio-box-fallback`），掩膜分支（`op-area-ratio-mask`）拿不到数据。
- **`model_id` 是权重文件名，不是市场 `modelId`**。`YoloDetector.model_id` 取 `Path(model_path).stem`（`yolo11n`），而 `models/registry.json` 里对应条目的 `modelId` 是 `ultralytics-yolo11n-coco-dev-pt`。观测信封的 `model.modelId` 因此无法与市场条目和 Manifest 对齐，存证追溯会断在这一环。`M08-T09` 按流绑定模型时必须把注册表 `modelId` 注入 detector，不能继续用文件名兜。
- **`sourceId` 与 `stream_id` 字符集不一致，没有映射表**。`stream_id` 允许 128 字符，告警 Schema 的 `sourceId` 只允许 64 字符的 `[A-Za-z0-9_.\-]`。`to_observation()` 现在遇到不合规的 stream_id 直接抛 `ValueError` 并提示调用方显式传 `source_id=`，不做静默截断（截断会让不同流撞成同一个 `sourceId`，进而串掉冷却与去重状态）。映射规则由 `M11-T03` 定，建议建流时分配一个短 `sourceId` 而不是从名字推。
- **`captured_at_us` 是服务端墙上时钟 + 单调夹紧**。接入层用 `time.time_ns() // 1000` 并对同一路流取 `max(prev, now)`，满足规格 §4.1「同源单调不减」，但 NTP 回拨时会出现一段时间戳压平（多帧共享同一微秒值）：不抛错，代价是 `RATE` 窗口与 `DWELL` 的时间推进短暂停滞。根治要让推流端带上采集时间戳，是否给协议加字段留给 `M08-T05`/`M11-T03`。
- **叠加画不出中文标签**。`cv2.putText` 只有 Hershey 字体，`format_label()` 直接画权重原始类名（ASCII）。Manifest 里的中文显示名到叠加层就落不了地；管理页要中文得在前端画。要烧进视频帧需要引入 PIL/FreeType 与字体文件（体积与字体许可证两个问题），得单独立任务。
- **`inference_ms` 首帧含预热**。实测 CPU 上 bus.jpg 首帧 7324 ms（含权重加载与图构建），第二帧起才是稳态值。`M08-T02` 的编码 FPS 与容量压测不得采信首帧数字。
- **`latest_detections` 只有一个槽位**。旁路通道按「最新一帧」下发符合协议（客户端必须容忍跳号），但 `M11` 的 `RATE` 窗口与存证需要按帧序连续消费。`M11-T03` 接观测时建议在 `_yolo_worker` 内同步喂引擎，不要经过这个单槽位，否则高负载下会漏帧且漏得不可观测。
- **分类型结果被静默忽略**。`build_detections()` 只读 `results[0].boxes`，不处理 `results[0].probs`，`Detection` 也没有分类分支（Schema 里 `Classification` 是独立对象）。金样向量 `op-presence-frame-classification`（`frame:` 主体）在服务端还没有数据来源，`M11-T03` 需要补一条分类适配路径。
