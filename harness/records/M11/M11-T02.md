## 遗留问题

- **向量只被语料校验，没有被任何引擎执行过**。`VectorExecutionTests` 现在整类跳过（`Ran 83 tests OK (skipped=1)` 里的那个 skip）。因此期望值目前只有「按规格算出来」这一层保证，`M11-T05` 接上 `app/alerts/engine.py::run_vector` 时**很可能有向量先红**：按 C-2，先判定是规格没写清还是实现不对，不允许直接改 JSON 对齐实现。
- **写向量暴露了 11 处规格欠定义，已全部在本任务内先改规格再落向量**（`docs/alert-engine-spec.md` 548 → 583 行，`specVersion` 仍为 `v1`，Schema 未变）。其中 §12「冷却边界取 `≥` 且被抑制的命中不刷新窗口起点」与 §11「`endedAtUs` 不被抑制改写」是新增的语义承诺，`M15` 侧必须同步。
- **规格 §15 的示例事件与落盘向量已逐字段一致**（补上了 `sourceId`／`operator`／`startedAtUs`）。这条一致性目前靠人工维护，没有测试盯：后续改 `cooldown-severity-escalates.json` 必须同时改 §15 示例。
- **`expectedEvents` 是部分匹配**（§15.1 第 3 条：未列出的字段不比对）。多数向量刻意不写 `state`／`endedAtUs`／`notifySeverity`，只钉住该向量要证明的那几个字段；这既是设计也是缺口 —— 想把某个字段变成全局强约束，要回规格 §15 加规则，不是逐个 JSON 补字段。
- **「确认后停止提级计时」（§14.2）无法用向量表达**：`ConformanceVector` 只有观测与规则两个输入通道，没有处置动作通道。已在 README 单列一节说明，由 `M11-T06`／`M11-T09` 与 App 侧 `M15-T04` 的单元测试覆盖；若要纳入向量必须先改规格 §15 与 Schema 再解冻。
- **`metric:` 主体没有向量**：`METRIC_THRESHOLD` 是预留未实现算子，只以 `OPERATOR_NOT_IMPLEMENTED` 拒绝出现。解冻该算子时必须补一组标量向量。
- **`.venv` 仍无 `jsonschema`**：加载器用「按 Schema 解析出的枚举／正则／必填表」做定向校验，不是 draft 2020-12 元校验。真正的实例级 Schema 校验仍待 `M11-T10` 视依赖策略决定是否引入。
