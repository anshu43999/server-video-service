# M11-T04 实现多边形与线段 ROI 几何

## 完成摘要

实现 app/alerts/geometry.py：矩形/多边形/线段三形态 ROI 的纯函数几何层。构造期按 §5.1 拒绝四类退化输入（点数不足、相邻重复点含闭合边、面积为 0、自相交、零长线段、越界点），自相交按「非相邻边任何共点即拒、相邻边共线折回才拒」实现，直边上的多余共线顶点仍合法。判定按 §5.2：点在多边形内用奇偶射线法且边界与顶点算内，框归属取框中心（与 M07 整框包含的差异见 §17 第 11 条），ENTER/INSIDE/EXIT 用 relation_holds 统一表达且首帧无前一帧时二者都不成立。面积按 §8.1：交叠面积 > ε 才算相交（贴边不算），AREA_RATIO 分子用 union_overlap_area 做「重叠只算一次」的并集，实现为框边坐标压缩成网格后逐格裁剪 ROI，凹多边形按轮廓而非外接框裁剪。跨线用 §5.2 的 side(p)=(p.x-A.x)*d.y-(p.y-A.y)*d.x 无限长直线语义，线上点不跨越也不覆盖上一个非零符号，首个非零符号只记录。写实现前先按 §18 顺序改规格：补 §5.1 自相交定义与退化行的可实现判据、§5.2 跨线符号公式与 LEFT_TO_RIGHT 标签映射、新增 §5.3 ε=1e-9 数值约定、§6 第 4 步补形态与算子不匹配拒绝，规格 583 → 619 行且 26 项冻结断言不变

## 完成标准

ROI 支持矩形、多边形与线段三种形态：多边形提供点在多边形内与框和多边形相交判定，线段提供跨越方向判定；退化输入（少于三点、自相交、零长线段）在构造时被拒绝；几何为纯函数并有金样向量覆盖

逐条对应：

| 要求 | 落点 |
|---|---|
| 矩形形态 | `Roi(shape=RECT, rect=Box)`；`point_in_roi` 走边界闭区间快路径，`overlap_area` 走矩形交叠快路径；`_validate_rect` 拒绝零宽零高、越出画面（`x+w > 1`、`y+h > 1`）与「RECT 却带 points」 |
| 多边形：点在多边形内 | `point_in_polygon`（先查边界再奇偶射线）+ `point_in_roi`；`ContainmentTests` 覆盖内部点、四条边中点、四个顶点、凹缺口内部与缺口顶点 |
| 多边形：框与多边形相交 | `overlap_area`（Sutherland–Hodgman 用框的四条半平面裁剪 ROI 轮廓，凹轮廓裁出的零面积桥不影响鞋带面积）+ `intersects`（`> ε`）；`union_overlap_area` 提供 §8.1 的并集分子 |
| 线段：跨越方向判定 | `signed_side` / `side_sign` / `step_side` / `is_positive_crossing`；无限长直线语义，`LEFT_TO_RIGHT` 是 `side` 由负变正的标签而不是屏幕方向 |
| 退化输入构造期拒绝 | `Roi.__post_init__` → `_validate`：少于三点（`at least 3`）、自相交（`_self_intersection` 返回首个冲突边对）、零长线段（`zero-length line`），另含相邻重复点（含末点与首点）、面积为 0、越界点、形态与载荷不匹配、LINE 缺 `positiveDirection`；一律抛 `RoiGeometryError(code="ROI_GEOMETRY_INVALID")` |
| 几何为纯函数 | 模块只依赖 `dataclasses`／`enum`／`typing`；`PurityTests` 断言源码中无 `time.time`／`datetime`／`monotonic`／`perf_counter`／`Instant.now`／`currentTimeMillis`／`random`／`open(`／`requests`／`logging`，`Box`／`Roi` 为 `frozen=True, slots=True`，`points` 为元组，`EPS == 1e-9` 与规格 §5.3 一致 |
| 引擎不含业务类别名 | `PurityTests.test_no_business_class_name_in_the_engine_source` 按整词匹配八个业务词（`person`／`helmet`／`vest`／`material`／`fire`／`smoke`／`phone`／`excavator`） |
| 有金样向量覆盖 | `reject-roi-geometry-degenerate`（三个退化 ROI 全部构造期拒绝）、`geometry-edge-touch-not-intersecting`（分子 0.06、占比 0.24，并证明「整框累加」得 0.48）、`op-line-cross-positive-direction`（四帧走一遍仅第 3 帧命中正向，`measuredValue` 与 `confirmedAtUs` 对齐）、`geometry-polygon-boundary-point`／`geometry-polygon-concave-notch`／`geometry-center-point-inside`／`baseline-m07-roi-inside-and-outside-unchanged`（命中主体集合 == `expectedEvents` 的 `subjectKey` 集合）；`test_every_geometry_vector_is_exercised_by_this_file` 兜底新增向量必须在本文件出现 |

## 遗留问题

- **掩膜分支未实现，`AREA_RATIO` 目前只有 `BOX_FALLBACK` 一条路**。`overlap_area` 只接受 `Box`，`areaSource: "MASK"`（§8.1）要求「掩膜多边形 ∩ ROI」，而 Sutherland–Hodgman 要求裁剪区域为凸，掩膜多边形不凸，需要换算法（凸分解或精确网格）。向量 `op-area-ratio-mask` 因此在 `M11-T05` 之前无法执行，该分支由 `M11-T05` 补齐。
- **§6 第 4 步新增的「形态与算子不匹配」没有金样向量**。本次只用 `RoiShapeMismatchError` 单测覆盖八个入口（LINE 被问内部／面积／轮廓，RECT 与 POLYGON 被问跨线）。双侧一致性靠向量裁判，App 侧可能实现成别的拒绝码；建议 `M11-T07` 落绑定检查时补一条向量。
- **`union_overlap_area` 的代价随框数平方增长**。实现是把框边坐标压缩成最多 `(2n−1)²` 个格子，每格再裁剪一次 ROI。单帧几十个框没问题，若 `M11-T05` 把它用在上百框的高密度检测上会明显变慢，届时换扫描线或先用 ROI 外接框剪枝。
- **越界容差的归属规格没写**。`_in_unit_range` 允许 ±ε，即 `1.0 + 1e-9` 仍算合法坐标。这是按 §5.3 的 ε 统一处理的推论，但 §5.1 只写「越界」没写容差；App 侧若用严格 `> 1.0` 判定，会在极端坐标上与服务端分歧。要么在规格里写明，要么补一条边界向量。
- **几何层不校验检测载荷**。`Box` 刻意容忍负宽高（面积按 0 计），缺字段直接 `KeyError`；载荷校验属于 `M11-T03` 的观测信封。目前没有任何测试守住「谁负责校验」这条分界，两个任务都做或都不做都能过测。
- **规格补写的四处是新增语义承诺，`M15` 必须同步**：§5.1 自相交定义（非相邻边任何共点即拒、相邻边只拒共线折回、直边上多余共线顶点合法）、§5.2 跨线符号公式、§5.3 ε=1e-9、§6 第 4 步形态不匹配。`specVersion` 仍为 `v1`、Schema 未变，但跨线公式把 `LEFT_TO_RIGHT` 从直觉名字改成了符号约定，按名字猜的实现会左右颠倒。
- **`relation_holds` 的首帧语义只有单测没有向量**。现有四条 ROI 向量都是单帧 `INSIDE`，`ENTER`／`EXIT` 与「首帧两者都不成立」需要多帧向量，要等 `M11-T05` 的求值器才能执行，届时补。
- **三项冻结风险与权限划分待定项延续 `M11-T01`／`M11-T02`**：`FR-M11-ALERT-CHANNELS`、`FR-M11-EVIDENCE-DEPTH`、`FR-M11-FIRE-DATA`，以及确认与误报标记的权限细分（`M11-T09`）、上游 Webhook 是「暂不做」还是「不做」未由用户确认。
