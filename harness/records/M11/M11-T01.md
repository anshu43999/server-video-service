# M11-T01 冻结公共告警引擎规格与 JSON Schema

## 完成摘要

产出 docs/alert-engine-spec.md（规格 v1，状态：冻结，共 18 节）与 docs/alert-engine.schema.json（JSON Schema draft 2020-12，22 个 $defs），作为服务端 M11 与 App 侧 M15 共用的唯一契约。规格明确这是告警引擎而非预警引擎，不做趋势外推与未来状态预测；引擎与具体模型和业务场景无关，场景通过场景包注入，引擎源码中不得出现业务类别名。三条硬约束：求值器是纯函数且时间只来自观测、金样向量是唯一裁判且冲突时先改规格、能力不足必须显式拒绝而非静默不触发。

## 完成标准

产出 docs/alert-engine-spec.md 与 docs/alert-engine.schema.json，唯一定义五层结构、subjectKey 五类（track/roi/metric/source/frame）、算子集与各自所需能力、三档严重级别、矩形与多边形与线段 ROI 几何、七类阈值及其运行时可改要求；明确求值器为纯函数且时间只来自观测；Schema 预留 RELATION、METRIC_THRESHOLD、COMPOSITE 与短视频存证并标注未实现；App 侧 M15 全部小任务以本契约为准

逐条对应：

| 要求 | 落点 |
|---|---|
| 五层结构 | 规格 §2：观测接入 → 特征聚合 → 规则求值 → 事件生命周期 → 投递处置，层间只允许单向数据流 |
| subjectKey 五类 | 规格 §3 五类表与四条约定；Schema `SubjectKey` 正则 `^(track|roi|metric|source|frame):[A-Za-z0-9_.\-]{1,64}$`、`SubjectKind` 枚举 |
| 算子集与各自所需能力 | 规格 §8 总表（允许主体 / 需要能力 / 用到的阈值 / 分档量）与 §8.1 逐算子语义；Schema `Operator` 枚举（8 个已实现 + 3 个预留）、`Capability` 六项 |
| 三档严重级别 | 规格 §10：`MINOR` < `MAJOR` < `CRITICAL`，明确不设「预警」档；§10.2 把 `severity`（事实）与 `notifySeverity`／`escalatedAtUs`（通知）分开 |
| 矩形与多边形与线段 ROI 几何 | 规格 §5 三形态 + §5.1 构造期拒绝表（自相交、零面积、零长度）+ §5.2 判定语义（射线法、中心点、叉积方向）；Schema `Roi` 以 `allOf` + `if/then` 按 `shape` 分支约束点数与 `positiveDirection` |
| 七类阈值及运行时可改 | 规格 §9 七类表 + 四条统一要求（运行时可改不重启进程、按来源覆盖、生效阈值随快照落库、借用第三方权重用更严默认值）；Schema `Thresholds` 八字段 + `Rule.severityBands` + `scope.thresholdOverrides` |
| 求值器为纯函数且时间只来自观测 | 规格 §1 C-1（禁用 `System.currentTimeMillis` / `time.time()` / `Instant.now()`）、§4.1（`capturedAtUs` 微秒且同源单调不减，违反抛错）、§11.3（空信封推进时间，断流不伪造告警） |
| Schema 预留三算子与短视频存证并标注未实现 | Schema 顶层 `x-notImplemented` + `Operator` 保留枚举值 + `Event.evidence.clipUri` 约束为 `"type": "null"`；规格 §8.2 与 §16 预留未实现清单（含拒绝码与解冻条件） |
| App 侧 M15 以本契约为准 | 规格 §0 两处实现表、§15 向量双侧共用且 App 原样复制、§17 与 M07 既有实现的差异表（逐条标注扩展／重构／行为变更）、§18 固定变更顺序（规格 → Schema → 向量 → M11 → M15） |
