## 0. 变更评审与停机门禁

2026-10-13 顺序修订：先完成 M33-T18 本地真实服务、PostgreSQL、管理后台与 Android 联合验收，再执行本任务的容器部署验收和正式环境发布准备。本节的镜像、云 PITR、在线 MinIO、生产停写与切流要求只约束部署/上线阶段，不作为本地测试的启动条件。T17 的既有离线演练证据保留；T18 本地通过不代表 T17 或正式上线通过。详见 [验收顺序决策](m33-local-acceptance-sequence.md)。

发布负责人在变更单记录旧/新完整不可变镜像及镜像摘要、Alembic 版本、云数据库实例与 PITR 恢复点、MinIO Bucket/版本化策略、四个 Docker 卷（或 Kubernetes PVC）和宿主机模型目录备份、TLS 域名/证书、媒体出口、回滚负责人和观察窗口。记录业务停写起止、最近一次实测隔离升级/恢复耗时、锁等待/磁盘预算，并留出人工排障及回滚冗余；不能用小数据演练秒数宣称生产 SLA。索引、复合外键和 inline 证据可能带来额外锁/容量开销；预检查需统计最大表、索引大小、证据字节和可用磁盘，缺少容量证据则取消窗口。

必须逐项取得可验证的 GO 结论，任一项失败均不切换：

1. 项目负责人书面决定 167 条无父告警投递回执的去向：优先找回可信历史告警；若无法恢复，单独批准可逆的原文归档及移出在线表。隔离演练不是此项授权。
2. 在线 MinIO 当前对象逐项可读，Bucket/前缀、SHA-256、访问授权和来源核对一致；不能把离线缓存复用当作在线可用。确认旧证据原对象和变更期间新对象的保留方案。
3. PITR/原生 PostgreSQL 备份、迁移格式 2 完整备份及受保护文件/对象备份均存在，已在独立空目标恢复，逐表、序列、结构、证据对象校验通过；记录恢复所需的数据库角色/扩展/授权，格式 2 备份不代替这些内容。
4. 已停止 API、设备上传、推流、告警/投递/复核后台任务及任何外部写库程序；从数据库连接/写入监测确认没有未停写者。`--maintenance` 是操作员确认，不执行实际停写；备份后源库产生变更则重新备份。
5. 账号和设备凭据接管人、项目负责人、证书与密钥轮换计划、审计留存及平台运维值班人员就绪；客户端理解显式项目上下文与旧接口有期限兼容边界。

## 1. 离线预演（Windows 开发/验收机）

只使用已经校验的私有 PostgreSQL 格式 2 旧库备份；不要把备份目录、原始数据库 URL、Token、证据图片放入工单或版本库。在 `server-video-service/` 执行：

```powershell
.\.venv\Scripts\python.exe tools/rehearse_multi_project_release.py --bundle backups\M33-T14-offline-rehearsal-v2 --postgres-bin D:\PostgreSQL\bin --run-regressions
```

该脚本通过私有临时目录、UTF8 PostgreSQL、回环监听和独立数据库验证原生 `pg_dump/pg_restore`、完整旧版恢复、独立升级与归档、幂等性、PostgreSQL 真正重启后新进程鉴权、成员撤权、设备凭据轮换、项目归档、审计留存/法律保留、有损降级拒绝及事后旧版恢复副本。`--run-regressions` 在同一临时实例的独立随机 schema 内运行迁移/凭据/报表回归。只输出摘要计数和耗时；结束时停掉临时实例并删除自身目录，停止失败则保留现场并报错。源备份先复制再恢复，结束对比原备份全部文件哈希；源业务库/线上 MinIO 不参与。原生 `pg_dump` 属于临时恢复库的副本，未包含生产数据库角色/全局授权/对象存储/宿主机文件，必须分别在上线环境备份和演练。

## 2. 生产发布顺序（仅在 GO 后执行）

1. 进入维护页并停写，保留旧完整镜像、配置、PVC/卷、数据源引用及数据库 PITR 时间点；将备份转移到访问受限的异地加密存储。生产运维可运行 `bash deploy/deploy.sh backup-db`；脚本使用 `umask 077` 生成受限文件，并以 `PGDATABASE` 环境变量传入 libpq URI，不把凭据放入 `pg_dump` 命令参数。环境仍对特权进程可见，因此必须限制备份主机的管理权限。另保留云数据库 PITR；禁止把连接串粘贴到终端历史、日志或变更单。`pg_restore --list` 是格式自检，不是恢复验证。
2. 通过受保护环境变量显式设置 `MIGRATION_DATABASE_URL` 为待升级源库，以及 `MIGRATION_RESTORE_URL` 为不同的空数据库或独立空 schema；核对两者不是同一实例/目标。运行 `tools/migrate_default_project.py inspect`、`prepare --bundle <全新私有目录> --evidence-root <实际证据目录>`、`verify --bundle <该目录>`，记录阻塞码/行数/哈希和版本，不输出原始行。严格使用 [迁移流程](default-project-rollout.md) 所列参数。
3. 执行 `restore --bundle <该目录> --maintenance`，在独立目标核对行、序列、结构、证据；然后只对被批准的源库执行 `apply --bundle <该目录> --maintenance`。如果书面批准历史归档且原文备份已验证，才显式追加 `--archive-orphan-receipts`；否则遇到 `orphan_delivery_receipts` 必须停下。不得补造告警、去掉外键或跳过对账。运行 `reconcile` 并确认 Alembic 为目标版本、默认项目固定 ID、账号/成员映射、孤立回执归档收据及各表归属。
4. 再切换两个完整不可变镜像与前端构建版本。Docker 用 `bash deploy/deploy.sh config` / `pull-up` / `smoke`；Kubernetes 在 Secret/ConfigMap 和镜像版本核对后 `kubectl apply -k deploy/k8s/production`，逐个确认 Recreate rollout 与健康。生产容器与配置必须保持 `RUN_DATABASE_MIGRATIONS=false`；启动钩子不是迁移作业。核对 TLS HTTPS/WSS、MediaMTX 授权回调及 WHEP/LL-HLS，不公开数据库、MediaMTX 控制端口或转换服务。
5. 用两个项目的负责人/用户和项目设备身份执行只读、写入、媒体、证据及模型的权限检查；成员撤权、设备轮换和项目归档应即时生效。检查审计与请求 ID、告警趋势、下载/视频首帧、归档只读、无跨项目明细；复用此前 M33-T18 的本地 Android 全流程用例，在部署环境再次验证关键链路，不能把本地结果直接当作部署后结果。满足线上验收后分阶段开放写入并观察异常率、告警送达、CPU/存储/索引与媒体错误，再关闭维护。

## 3. 故障、回滚与不可逆边界

迁移前失败：保持旧版镜像与旧库，仅修复预检查或备份，重新评审窗口。事务内迁移失败：确认事务回滚和旧版结构/行数，再决定是否重试；不能假设失败只影响镜像。迁移提交后但尚未开放新写入：立即再次停写，保留升级后库和审计，**另建空目标**恢复完整升级前快照并核对原始 176 条回执（包括 167 条历史孤立回执）、账号、会话、证据、序列及卷/对象；用旧版完整镜像和兼容配置指向恢复库，隔离验证登录与核心流程后再切流。不要直接对已有项目/审计数据运行 Alembic downgrade，也不要就地覆盖源库。

已开放新项目写入后，不存在自动无损回退至单项目版本：新项目、成员、设备凭据、项目模型分配和审计无法由旧版表达；必须保留升级后副本，逐项评估回放/导出、新旧证据对象及丢失窗口，经业务负责人批准后另行恢复。旧版镜像仅配套已恢复的旧 schema；`kubectl rollout undo` 或改回镜像标签不构成回滚。重大泄露时优先隔离入口和撤销受影响设备凭据，再冻结取证，不能通过直接删库恢复授权。回滚后验证与告警观测仍要持续，并记录操作人/开始结束时刻和剩余风险。

## 4. 安全、审计与告警值班

- 人类账号采用动态 Session，项目成员及能力每次请求复核；禁用账户/移除成员后用原会话和媒体连接确认失效。设备凭据单项目、最小能力、短有效期；轮换使用 `expectedRevision`，旧凭据立即失效，确认新的机器写入成功后安全分发；泄露则先撤销/轮换、检查最近使用和项目审计。服务端 MediaMTX 内部 Token、转换 Token、模型 Ed25519 私钥、数据库/MinIO 账号均分别轮换，记录新旧重叠窗口和依赖切换；不得在 API 返回、日志或聊天中输出。签名公私钥不能靠更换服务器私钥而自动更新 Android 内置公钥。
- 所有控制与媒体入口经可信 TLS（HTTPS/WSS），反向代理转发鉴权且不记录 Authorization/Cookie、完整 URL 查询串、RTSP 密码、证据或一次性凭据响应。MediaMTX 控制面只在内网；数据库、对象存储及备份开启访问审计。恢复/调试临时 `trust` 仅用于离线回环实例，不复制到生产。
- 每日监控 401/403/404/409 异常比例、同一设备 nonce 重放、孤立告警/投递计数、MinIO 对象读错、数据库连接/锁等待/备份与 PITR 新鲜度、审计写入/留存任务、服务/MediaMTX/转换健康、WebSocket/WHEP/LL-HLS 错误和项目交叉访问拒绝。设值班升级阈值和实际通知通道；此文档未声称生产已有 Prometheus/通知规则。定位时从响应 `X-Request-Id` 到结构化日志，再查当前项目审计；不得用客户端提交的 ID 或 `X-Project-Id` 作为已验证身份。
- 项目与平台审计留存用 `tools/retain_project_audits.py --days 365` 先预览、按法定/诉讼保留清单加 `--hold-project`，在已验证备份和正式审批后才使用 `--apply`；最短 90 天，默认不自动删除。轮换、恢复、留存执行结果及失败日志应进入受控变更记录，不放原文凭据。排障参见 [项目审计与日志](project-reporting-observability.md)、[设备凭据](project-service-principals.md)、[TLS 边界](production-security.md)。
