# 冻结的暂不可测试项

更新时间：2026-09-02  
适用阶段：M01 移动端联调协议与真实视频链路

## 冻结原因

当前开发环境执行 `adb devices` 未发现 Android 真机或模拟器，无法诚实完成 Android 播放器现场验证、弱网测试和长时间运行测试。VLC 进程也未能在当前环境提供可定位的播放退出结果，因此不把“进程启动”视为播放通过。

## 已完成且不冻结的内容

- 服务端本地视频文件 → ingest WebSocket → output WebSocket 闭环；
- MJPEG `multipart/x-mixed-replace; boundary=frame` 契约；
- WebSocket binary JPEG 契约；
- 流协议、错误码、鉴权占位、推帧工具和输出探针；
- 13 项服务端自动化测试和端到端本机基准。

## 暂时冻结项

| 项目 | 当前状态 | 解除条件 | 影响 |
|---|---|---|---|
| Android 播放器兼容性 | 冻结 | 目标 Android 设备/模拟器和播放器库可用 | 暂不能确认移动端实际播放能力 |
| Android 断线重连 | 冻结 | Android 现场网络切换测试环境可用 | 暂不能确认 App 重连体验 |
| 弱网、丢包和长时间运行 | 冻结 | 弱网注入工具和目标设备可用 | 暂不能确认跨网络 P95 延迟、掉帧与稳定性 |
| VLC 播放对照 | 冻结 | VLC 命令行可返回可定位播放结果 | 暂缺少桌面播放器对照证据 |

## 解冻方式

满足以下条件后，新建或恢复专门任务补测，不回写或伪造本轮历史结果：

1. 提供 Android 真机或可用模拟器；
2. Android 播放协议已由 [ADR-002](adr-002-production-transport.md) 定为 WebRTC/WHEP（回退 LL-HLS），补测按该协议进行，不再补测 MJPEG/WebSocket JPEG 的移动端播放能力；
3. 提供真实推流设备/测试视频和弱网测试方法；
4. 记录设备型号、Android API、WebRTC 库版本、输入输出 FPS、P50/P95 延迟、回退次数和重连结果。

冻结不等于删除需求；它只表示本轮允许依赖服务端自动化结果继续开发，现场兼容性仍是发布前门禁。

## ADR-002 之后的变化

本文冻结的四项在新协议下依然冻结，但验证对象改变：Android 播放器兼容性和断线重连要按 WHEP/LL-HLS 补测，不再按 MJPEG/WebSocket JPEG 补测；"已完成且不冻结的内容"中的 MJPEG 与 WebSocket JPEG 契约仍然成立，但只作为诊断通道的契约，不构成生产播放能力的证据。
