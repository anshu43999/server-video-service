# ADR-003：服务端接入、PC实时预览与分析告警，退役移动直播分发

日期：2026-10-15。状态：经用户再次确认修订；实施和验收由 M34 / Android M101 跟踪，不代表代码全部交付。

## 范围纠正记录

2026-10-15 用户确认：保留后台/PC的视频流接入、实时画面查看和实时YOLO分析；只取消PC推流及移动端远程视频直播/收流。此前将PC预览与视频墙一并退役属于范围理解偏差，现由M34-T03修正。M34-T01/T02已完成记录保留为历史，不改写其当时结果；后续任务与本ADR以本次澄清为准。Android M101仍负责移除移动端远程入口和实现，其“无直播请求”限定Android客户端；不得据此取消PC后台预览。

## 决策与边界

用户取消 PC 远程推流与 Android 远程直播/收流。新链路：项目视频源 → 服务端拉流/解码 → YOLO → 告警规则 → 正式告警持久化及证据 → 告警查询、处置和提示。没有播放客户端时分析仍运行，逐帧检测不是正式告警，不能逐帧入库或通知。

保留：管理员/负责人按项目维护视频源、模型绑定、分析参数、启停和运行错误；PC具有项目查看权限的登录用户可查看实时预览/视频墙；关闭YOLO显示原画面，开启后可显示识别叠加；图片/相机本地巡检；账号/成员/权限/隔离；模型下载；服务端正式告警及历史 SERVER_STREAM/streamId 溯源；证据图片及已存短视频。

退役：发布编码器、MediaMTX 推流及 WHEP/LL-HLS/RTSP 播放分发；旧通用MJPEG/JPEG实时出口和客户端逐帧检测订阅；PC推流、分发地址及播放分发诊断；Android远程视频入口、流列表、播放器、重连与直播SDK。RTSP输入解码及PC按需预览编码不等于发布编码器，不能一并删除。

## PC专用预览契约

- `GET /aiyoloapi/projects/{project_id}/streams/{stream_id}/preview`仅供后台同源登录Cookie及项目`project.streams.view`权限访问；不接受Bearer请求、旧静态令牌或服务主体凭据，不允许跨站资源读取。这里隔离的是访问通道和权限，不声称识别或禁止某类物理设备；同一合法账号在浏览器登录仍可按权限使用后台。
- 每次请求返回当前JPEG快照（200）及`X-Preview-Mode: raw|yolo`；暂无帧或来源超过3秒未更新返回204并清屏；项目不可见或流不存在404，未登录/会话失效401或403。旧`mjpeg/playback/ws/detections`契约继续退役，不新增移动播放地址。
- 预览最高5帧/秒、最大宽度1280，按需编码并共享短时缓存；不生成H.264发布进程。YOLO分析保持原独立帧率、latest-only和正式告警规则，不受预览帧率、观看人数或页面关闭影响。此预览不是25/30fps全帧率播放器。
- 原帧与对应推理结果仅有界保存在内存，不持久化直播；YOLO故障时保留原画面并呈现模型状态。标注只用于匹配的帧及有效模型代次，超过2秒不展示陈旧标注。
- 权限在请求和编码后复验；会话撤销、成员撤销、项目停用、模型切换/撤权及流关闭均不得返回失效结果。前端切项目/离页取消请求并释放图片，204、断网或错误清空旧图，断流恢复可重新预览；浏览器已收到的单帧不可能远程收回。

## 兼容、安全与数据

- 旧通用播放/预览HTTP入口统一410（live_video_retired），不返回移动播放地址；旧直播/检测WebSocket关闭1008。退役入口一致失败，不查询或泄露资源。受保护的输入接入和新的PC专用预览保留。
- 旧MediaMTX开关即使true也不能重新启用发布。旧数据库流/绑定/告警/证据不删除；已完成历史记录不改写。
- 告警仍经既有规则、冷却去重和持久化生成。通知只引用已持久化且当前项目可见的正式告警；重连、重复投递和项目切换不得重复入库或错误提示。
- 推理期间关闭YOLO、切模型、撤销授权、关闭会话时丢弃过期结果；关闭后不得产生迟到告警。告警/证据失败需可观测，不能被推流状态掩盖。
- 保留Media3证据播放器、服务连接设置、历史证据、CameraX和图片识别；旧REMOTE_STREAM保存状态回到安全页面，不能恢复直播。

## M34-T04 配置与运维实施

运行配置移除全部 `mediamtx_*` 与 `max_output_subscribers`，旧环境字段仅忽略，不可恢复分发；旧鉴权端点保留为不读取凭据/项目/数据库的403墓碑。发布器、H.264编码器与发布容量实现删除；旧容量/播放工具退出2并明确标记retired，避免误出验收数据。

Compose/K8s移除媒体服务/端口/依赖，Windows启动不再启动MediaMTX且拒绝旧参数。保留OpenCV/FFmpeg输入解码、PC按需JPEG预览、四个卷、外部PostgreSQL/MinIO和输入出站网络；未更改数据模型或流记录。旧部署孤立容器/集群对象人工维护与禁止回退恢复分发的门禁见[升级手册](media-retirement-upgrade.md)。仅完成静态配置/隔离回归，不表示T05/T06或Android已完成，也不授权容器部署。

## M34-T05 独立告警与通知实施

规则确认、证据/事件持久化、通知调度与PC观看人数无关。结束状态提交失败保留活动事件；重启不重复创建仍在持续的已ACK事件。通知发送与回执写库分别重试，写回执失败不得重新发送已成功通知。告警WS发送前及空闲期间复验权限并清理断开连接。

PC使用项目全局告警同步、首次历史基线、连接恢复补取及5秒REST兜底，按项目/事件去重提示；切项目、撤权和整机断网继续清空数据并按原门禁重新验证。完整契约及“站内通知不等于离线系统推送”、真实验收边界见[独立告警通知](independent-alert-notifications.md)。Android产品实现和真实三端联合验收仍由M101/M34-T06负责。
