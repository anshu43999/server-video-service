# 多模态复核需求与职责边界

## 1. 目标

多模态复核用于在告警生成后，对证据图片、检测结果和事件上下文提供辅助判断，帮助值班人员区分真实告警、疑似误报和无法判定。它不是第二条告警引擎，也不替代人工处置。

本任务只交付管理后台静态演示原型和需求契约，不实现真实供应商调用、不发送真实图像、不以 Mock 数据证明模型效果。

## 2. 触发与去重

- 只有满足显式配置的规则、严重级别或人工发起条件时才触发复核。
- 以 `eventId` 作为去重键，同一事件最多发起一次复核；重复请求返回已复核/进行中的状态。
- 每日调用次数必须受配置上限约束。达到上限后保留原告警并标记额度不足。
- 复核记录至少包含事件 ID、触发原因、模型 ID、提示词版本、开始/结束时间、耗时、来源和结论。

## 3. 结论口径

允许的展示状态包括：

- `UNREVIEWED`：未复核；
- `CONFIRMED`：复核确认；
- `SUSPECTED_FALSE_POSITIVE`：疑似误报；
- `INCONCLUSIVE`：无法判定；
- `FAILED`：复核失败；
- `HUMAN_REVIEWED`：人工复核/确认。

所有状态都只标注，不删除、不覆盖原始告警。人工确认仍是最终处置动作。

## 4. 失败与 fail-open

超时、鉴权失败、限流、额度不足、供应商不可用、响应格式错误和内部异常统一采用 fail-open：

1. 原告警继续保留并可正常投递；
2. 复核状态标记为 `FAILED`，记录可审计的失败原因；
3. 不阻塞视频流、推理、告警生成、告警投递或处置接口；
4. 不自动重试同一事件，除非后续策略明确允许且仍未超过每日上限。

## 5. 图像出站与密钥安全

图像出站默认关闭。管理员必须在配置页显式开启，并完成二次确认后，系统才允许向外部供应商发送证据图片。未开启或未授权时，页面必须明确提示“不会发送任何图像”。

供应商密钥只能通过服务端安全配置或密钥管理系统注入。前端只显示掩码；日志、测试夹具、Mock 数据、审计记录和训练集导出均不得包含明文密钥、Authorization 值或本机绝对路径。

## 6. 端侧与服务端职责

端侧复核适用于本地相机或用户主动选择的图片，负责设备侧预览和用户交互；服务端复核适用于远程视频告警，负责统一触发、事件去重、每日额度、权限、审计、结果标注和失败降级。

端侧与服务端共享结论状态和展示契约，但不能互相覆盖原始告警事实。远程视频的服务端告警仍由服务端规则引擎产生。

## 7. 真实接入前置条件

真实模型调用前必须完成：

- 供应商服务条款、数据处理和隐私合规评审；
- 密钥托管、轮换、权限分级和日志脱敏；
- 图像出站授权、地域和网络边界确认；
- 每日/每月费用上限与限流策略；
- 模型、提示词和版本可追溯；
- 真实业务样本上的准确率、误报率、延迟和失败率基线；
- 端侧与服务端产物、结果字段和回退策略联调。

## 8. 原型验收范围

M25 原型应提供：

- 智能复核导航和配置页；
- 成功、鉴权失败、超时、额度不足四类连接测试 Mock 反馈；
- 告警列表和详情中的复核状态、理由、模型 ID、提示词版本、耗时和来源；
- 人工确认误报的 Mock 操作；
- 今日、近 7 天、近 30 天的调用量、结论分布、失败原因和误报率对比看板；
- DEMO MODE/Live API 语义与既有管理后台一致；
- 既有告警处置、证据图片和报警推送功能不回归。
