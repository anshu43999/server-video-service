# ADR-003：模型来源与许可证决策

状态：**accepted（冻结）**  
日期：2026-09-04  
适用任务：`M09-T08`  
关联任务：`M09`、`M06`、`M10-T01`

## 1. 背景与问题

模型市场需要同时服务服务端推理和 Android 端推理。模型文件、训练数据、导出工具和应用代码的许可证并不等价，不能因为 App 代码或运行时采用 Apache-2.0/MIT 就推断权重可以商业分发。当前登记的 YOLO11n 文件来自 Ultralytics 官方发布链路，并以 COCO 开发资产完成转换；它们可以用于内部开发链路验证，但不能在没有授权结论时进入对外交付形态。

官方 YOLO 系列权重的可获得范围也必须和业务场景区分：官方预训练权重覆盖 **COCO** 与 **ImageNet**（ImageNet 权重用于分类/特征初始化，不提供智慧工地检测类别）。安全帽、反光衣、烟火、抽烟、物料状态等工地类别不是官方权重自带类别，需要另行获得有授权的训练数据和微调权重。

## 2. 决策

采用**路线 A：保留 Ultralytics YOLO 系列，购买并留存适用于本产品交付范围的 Ultralytics Enterprise License；模型层保持可替换**。

“模型层保持可替换”意味着业务规则、检测信封、场景包和市场 API 不得依赖 Ultralytics 私有 API 或固定类别索引。替换模型时只需提供相同的场景 Manifest、原始类名标签、输入/输出描述和产物校验值；推理适配器可以替换，告警引擎和客户端契约不变。

Enterprise License 的合同、授权主体、覆盖版本/部署形态和有效期必须作为发布证据保存；在证据落盘前，现有 `releaseEligible=false` 的开发模型继续保持不可分发。

## 3. 官方权重与第三方场景权重边界

| 来源 | 可用于 | 不得推断 |
|---|---|---|
| Ultralytics 官方 COCO 权重 | 通用目标检测开发、链路和性能验证；COCO 80 类原始标签 | 不代表安全帽、反光衣、烟火、抽烟或工地合规精度 |
| Ultralytics 官方 ImageNet 权重 | 分类/特征初始化及研究验证 | 不是可直接用于本项目检测市场的工地检测模型 |
| 经过授权的社区/业务微调权重 | 对应场景包的候选模型；须记录数据集许可、训练者授权和 SHA-256 | 不能仅凭公开下载地址或仓库代码许可证进行商业上架 |

当前已核实的可获得性显示，工地 PPE 候选权重主要集中在同一份 Roboflow 数据集；该数据集的使用范围、再分发权和训练产物权利必须单独核实。没有可验证授权的数据或权重只可列为候选，不得标记为 `releaseEligible=true`。

## 4. 智慧工地场景包收敛

MVP 将场景收敛为四组。四组是目录和规则模板的业务边界，不表示当前仓库已经拥有可发布的四套权重。

| 场景组 | 目标能力 | 首选标签来源 | 当前状态 |
|---|---|---|---|
| 工地合规 | 人员与 PPE/作业合规对象的检测，供 ROI 和规则组合 | 经授权的 PPE/业务微调权重；必要时以 COCO `person` 作为基础类 | 需业务数据、授权和现场验收；COCO 不能替代 PPE 类 |
| 烟火 | 火焰、烟雾等安全事件的候选检测 | 经授权的烟火数据集与微调权重 | 待获得权重与许可证；规则可先用金样向量验证 |
| 抽烟 | 人员抽烟行为/烟具的候选检测 | 经授权的行为数据集与微调权重 | 待获得权重与许可证；单帧行为误报风险高，需现场重测 |
| 物料现场 | 材料堆放、常见工器具和物料对象检测 | COCO 中可复用的原始物体类 + 经授权业务微调类 | 仅 COCO 类可先做链路验证，业务类仍需授权数据 |

### 4.1 被移除的类别（逐条）

下列类别从首批场景包候选清单中移除，而不是伪造为“已有模型”。原因均写入目录规划，后续只有在取得权重/数据和授权证据后才能重新提出：

| 移除类别 | 移除原因 | 重新纳入条件 |
|---|---|---|
| 安全带 | 当前可获得的工地 PPE 权重未提供可验证的安全带类别/授权 | 有明确类别标签、训练/再分发授权、产物哈希和现场验收集 |
| 摔倒 | 属于时序行为，不是单帧目标检测；现有候选权重没有可复核的时序定义 | 提供经授权的视频数据、时序模型或规则定义及验收指标 |
| 渣土车未苫盖 | 需要“车辆 + 苫盖状态”的细粒度属性，公开候选权重不可获得且标签定义不一致 | 提供授权数据、状态标签规范和误报/漏报验收集 |
| 焊接火花 | 小目标、强光和遮挡导致通用 COCO 权重不覆盖；当前无可验证业务权重 | 提供授权的焊接火花数据、最小目标尺寸和现场安全验收 |
| 裸土积水 | 属于场地状态/分割或场景分类，不是 COCO 目标类；当前无可验证权重 | 提供授权影像、分割/分类标签和季节/光照覆盖验收 |
| 吊钩 | COCO 不含吊钩，现有目录没有可验证的吊钩权重和授权 | 提供授权吊钩数据、遮挡规范、产物哈希和现场验收 |

“安全帽、反光衣”等 PPE 类别不因名称常见而视为官方权重能力；它们必须遵循同一授权和验收门槛。`person`、`bottle`、`backpack` 等 COCO 原始类只能按其原始语义使用，不得在 Manifest 中重命名成业务类来规避缺失能力。

## 5. 标签契约

1. 推理输出和跨端 JSON 契约使用权重的**原始类名**，并保持权重原始顺序；例如 COCO 的 `person`、`bottle` 必须原样传递。
2. 中文显示名、业务别名和规则模板映射只存在于场景 Manifest 的映射层（如 `labelDisplayNames`），不得写入推理适配器或告警引擎源码。
3. Manifest 的 `labels` 是稳定接口的一部分。删除、重排或复用索引都视为模型版本变更；转换产物必须重新登记并计算 SHA-256。
4. 当模型不提供规则所需类别或能力时，服务端必须显式拒绝/标记不兼容，不得静默把相近类别当作替代。

## 6. Manifest 元数据要求

所有模型及其每个可分发产物都必须在单一登记源（`models/registry.json` 或其导入 Manifest）中记录以下字段：

```json
{
  "modelId": "authorized-scene-v1",
  "version": "1.0.0",
  "scenario": "site-compliance",
  "runtime": "server-onnx",
  "labels": ["person", "bottle"],
  "labelDisplayNames": {"person": "人员", "bottle": "瓶罐/异物"},
  "license": {
    "spdx": "LicenseRef-Ultralytics-Enterprise",
    "status": "approved",
    "sourceUrl": "https://www.ultralytics.com/license",
    "evidenceRef": "compliance/licenses/ultralytics-enterprise-<contract-id>.md"
  },
  "sourceUrl": "https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo11n.pt",
  "upstreamVersion": "ultralytics==8.4.123",
  "artifacts": [{
    "artifactId": "server-onnx",
    "format": "onnx",
    "platform": "server",
    "path": "models/authorized-scene-v1.onnx",
    "sizeBytes": 0,
    "sha256": "<64-hex>"
  }]
}
```

其中：

- `license` 至少包含 `status`；商业发布时应包含 SPDX/许可证引用、许可证来源 URL 和授权证据引用；
- `sourceUrl` 是上游权重或业务权重的公开/受控来源地址，不得写本机绝对路径或访问令牌；
- `upstreamVersion` 固定训练/导出所依赖的上游版本（例如 `ultralytics==8.4.123`），不能只写本地文件名；
- `sha256`、大小和相对产物路径继续由 M09-T02 的启动校验强制验证；
- 现有 COCO 开发模型保持 `releaseEligible=false` 和 `licenseStatus=internal-development-chain-validation-only`，直到 Enterprise License 与数据集许可证据完成审核。

## 7. Apache-2.0 备选路线与触发条件

路线 B（Apache-2.0 或其他经法务批准的宽松许可证模型链）不是当前默认路线，只有在以下任一条件满足并完成新 ADR/变更评审时触发：

1. Ultralytics Enterprise License 未能覆盖目标部署形态、地域、客户交付或续期成本不可接受；
2. 许可证审查发现 AGPL/商业授权义务与产品交付模式冲突，且无法通过合同补救；
3. 业务方要求完全离线、可再分发且不依赖 Ultralytics 授权的模型链；
4. 已获得 Apache-2.0（或法务书面确认兼容的许可证）推理代码、权重、训练数据/数据集和导出链的完整证据，并在同一场景验收集上达到路线 A 的功能与性能门槛。

触发后必须：冻结新的 `sourceUrl`、`upstreamVersion`、许可证证据和 SHA-256；重新转换服务端/Android 成对产物；更新场景 Manifest 与客户端兼容性；完成 M10 的发布签名/供应链拆解前，不得将“Apache-2.0”文字当作已经批准的商业结论。

## 8. 影响与未决风险

- M09-T05 可以复用目录、下载和校验流程，但首个业务模型上架必须等待许可证闸门和成对产物；
- 烟火、抽烟以及 PPE 场景的精度、误报和数据偏差仍需现场重测，不能用 COCO 指标替代；
- 本 ADR 不授予任何第三方数据集或权重的使用权，也不替代法务对合同、数据集条款和客户交付范围的审查；
- M10 继续承接数字签名、密钥保管、灰度发布和发布证据，不在本 ADR 中实现签名逻辑。
