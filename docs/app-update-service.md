# App 版本发布、地址、回执服务与管理后台（M42-T05～T07）

对应 FR-12；线格式以 [冻结契约](app-update-v1.md)、schema 和共同金样为准。
已实现服务接口、存储集成、版本管理和快速回退界面；Android 安装及生产部署由后续任务承接。

## 配置与启用

默认 `APP_UPDATES_ENABLED=false`，不会生成或自动批准生产身份、证书和私钥。
启用需要已迁移数据库、已核验工件，以及：

| 配置 | 用途 |
|---|---|
| `APP_UPDATE_KEY_ID` | 独立 App 元数据密钥标识 |
| `APP_UPDATE_PRIVATE_KEY_PATH` | 挂载的 Ed25519 PKCS8 PEM 私钥；禁止复用模型或 APK 签名材料 |
| `APP_UPDATE_SCOPES_PATH` | 运维维护的 JSON scope 数组；公共入口严格匹配四元组 |
| `APP_UPDATE_RECOVERY_EVIDENCE_PATH` | 可选受控 CI 恢复验证记录 JSON 数组，缺失时只允许无恢复包止损 |
| `APP_UPDATE_SERVER_CONTRACT_VERSION` | 当前服务协议版本，默认 1 |
| `APP_UPDATE_GATE_CAPABILITIES` | 可限制的在线能力名，逗号分隔；默认空意味着禁用门禁发布 |
| `APP_UPDATE_MAX_DEVICES` | 每策略已联系安装实例上限，默认 100000 |
| `APP_UPDATE_MAX_RECEIPTS_PER_DEVICE` | 每策略/实例回执上限，默认 10000；重复重试不占新名额 |
| `APP_APK_DOWNLOAD_ENDPOINT` | 可选公开 HTTPS S3 网关；上传可继续使用内部 MinIO 地址 |

scope 文件示例（应使用实际配置的发布者和部署）：

```json
[
  {
    "contractVersion": "app-update/v1",
    "publisherId": "enterprise-primary",
    "packageName": "com.aiyolo.inspection",
    "channel": "enterprise-stable",
    "deploymentId": "enterprise-production"
  }
]
```

`AppIdentity.metadata_key_config_ref` 必须等于活动 `APP_UPDATE_KEY_ID`；`approved_signer_sha256` 必须显式批准。
配置缺失或不一致返回 `service_unavailable`。私钥仅由配置加载，不进数据库、审计或响应。
已有模型私钥配置时比较公钥字节，拒绝同一把密钥，即使 PEM 文件路径不同。
生产轮换、吊销和跨实例限流等加固由 T08 覆盖；当前不提供响应驱动的公钥发现。

## 发布流程

### 简化主要操作（M42-T11，2026-10-30）

管理员自行打包并签名 APK，自己上传到 MinIO 或第三方文件托管空间，在「平台管理 → App 版本管理 → 新建版本」统一填写版本名、递增版本码、公开 HTTPS 直链、更新说明、提醒级别及审计原因。只有一个部署/渠道时自动选定；有多个范围时明确选择。原始下载域名自动加入允许列表，跨域跳转需在高级设置补充域名。

点击「核验 APK」复用 external-artifacts 持久队列，服务端完整下载一次进行现有 SDK、SHA-256、大小及批准证书核验，临时文件按现有策略清理。用户填写的版本必须与真实 APK 一致；不一致时保留输入并显示真实版本，禁止创建草稿。核验后点击「创建版本草稿」，再在版本详情核对来源并「配置并发布」。不自动发布；普通/重要/兼容门禁及停止、恢复流程沿用现有接口。

此路径不使用业务服务的 MinIO 上传密钥；手工上传到 MinIO 的公开 HTTPS 直链按 external/public 来源处理。服务端核验时仍需要一次 APK 入站流量与 SDK/兼容配置，App 下载流量直接到托管源。既有 APK/元数据签名配置、权限与 App 安装确认仍适用。当前只接受公开 HTTPS 直链，不接受 HTTP。

关闭向导停止浏览器轮询与未完成请求，不撤销已接受的后端核验作业。已登记结果可从「安装包与来源」继续操作；未提交的表单不持久化，离页需重新填写。同内容重试复用幂等键，冲突需要关闭、刷新、核对后继续。原「登记外链」「上传 APK」移入「其他安装包操作」，保留已交付能力。

1. T03 上传或 T04 外链登记完成实际字节与 APK 签名核验，工件/来源均为 verified。
2. 平台管理员 POST `releases` 创建草稿；首次创建范围策略，修订为 1。
3. GET 发布详情获得当前策略修订，GET 工件来源选择来源 ID/修订。
4. POST `{releaseId}/publish`，传预期策略修订、来源、最低支持码及能力列表。
5. 事务锁定 App 身份、重读管理员权限，检查工件、证书、来源摘要、大小、可达记录及兼容能力。
6. CAS 增加策略修订，保存签名策略历史、发布状态及审计。同操作者/动作/幂等键重试返回原结果。

发布只能使用草稿，已发布或停止的版本不能原地更换工件/地址。新发布正常版本必须高于仍活跃的目标。
同一个工件可以有多个已核验来源；发布后固定一个来源，另选来源需要后续策略操作，不能修改现有来源字节。
普通、重要推荐通过 importance 表达；门禁要求最低支持码大于 1 且能力列表非空。
禁止限制升级、诊断、退出、恢复和本地数据；只接受配置中明确列出的在线能力。
最低码不得高于目标，已联系且低于门槛的设备必须有可兼容目标；未知设备不施加没有可安装目标的门禁。

POST `{releaseId}/stop` 原子停止分发并清除兼容门禁，之后不签发该发布的新地址/安装许可。
不删除公开文件，不撤销已经交给系统安装器的操作，不将停止等同回退完成。
高版本恢复和未准备恢复包时的止损使用下面的回退流程。

## 快速回退与恢复（T07）

在已发布或已停止版本详情点击「快速回退与恢复」，选择全部问题版本、仍已发布的普通稳定版本，以及可选的更高版本码普通草稿作为恢复包。

1. 「预览影响」调用冻结的 rollback-preview，读取策略、工件、来源、兼容证据及已联系设备，不创建作业、审计或设备记录。问题版、稳定版及恢复包均须属于同一策略和批准身份。
2. 预览指纹由独立元数据密钥签名后取摘要，绑定请求、策略、全部 APK 摘要和兼容字段、稳定及恢复来源修订/定位、证据和阻塞项；五分钟时间窗内有效，返回精确 expiresAt。跨进程使用相同密钥可验证，过期、来源或证据变化必须重做预览。
3. 填写原因并确认，提交幂等键、预期策略修订和指纹；在身份锁和单一事务中停止问题版、清除兼容门禁、恢复稳定推荐、必要时将草稿发布为恢复包并保存签名策略历史和审计。任何校验、签名或数据库失败整体回滚。
4. 无恢复包也可先止损，设备检查返回 recovery_pending。准备好恢复包后，使用同一组已停止问题版本和稳定版重新预览提交；只允许与先前 pending 操作精确匹配的问题版本集合。
5. 恢复包仅推荐给问题版本码的安装实例，未安装问题版的设备继续使用稳定推荐；所有下载及安装许可再次核对，不能用已停止问题版的旧许可请求取得新授权。停止恢复包后，对应问题版本重新进入 recovery_pending。
6. 结果分别展示策略生效修订与设备恢复阶段。操作可按 ID 重查，版本详情给出最近操作 ID。仅统计已联系且关联问题版/本次恢复尝试的设备，未知安装数量不伪造；打开安装器不算健康，健康仍为客户端回执。

恢复包必须同包名、同批准证书、版本码高于全部问题版，服务协议匹配，数据 schema 不低于问题版且可读取问题版 schema，SDK/ABI 不丢失问题版设备覆盖；已联系设备上下文必须兼容。工件及来源须已完整核验，可信构建兼容证据不可缺少。

受控 CI 恢复记录示例（只能由运维挂载，浏览器无录入/批准入口）：

```json
[
  {
    "stableSha256": "稳定工件的64位小写摘要",
    "affectedSha256": ["问题工件的64位小写摘要，排序"],
    "recoverySha256": "恢复工件的64位小写摘要",
    "preservesData": true,
    "restoresStableBehavior": true,
    "serverContractVersion": 1,
    "evidenceRef": "受控CI中数据迁移、行为恢复和兼容测试报告的不可变引用"
  }
]
```

上述文字占位需替换成真实摘要；不能用管理员填写一个证据路径代替数据迁移测试。该证据配置由可信部署维护，生产启用前必须验证其来源和报告内容。配置缺失不阻止无恢复包止损；配置格式错误会拒绝启动升级服务。

## 管理后台（T06）

入口为后台「平台管理 → App 版本管理」，路径 `/admin/platform/app-updates`。
仅启用的 PLATFORM_ADMIN 可见并可进入；项目管理员、操作员、查看者和 legacy token 不具备版本管理权限。
服务端每次请求重新检查账号，界面隐藏不能替代鉴权。

- 「安装包与来源」显示实际解析的版本、大小、SHA-256、批准 APK 证书摘要及 SDK/ABI/数据兼容范围。
- 「上传 APK」使用同源动态 cookie 和 multipart，显示真实发送进度，可中断；100% 仅代表文件发送完毕，必须等待登记响应与后台完整核验。
- 「登记外链」输入公开 HTTPS 直链及下载/重定向域名；后台核验一次完整文件，App 之后直连文件源。
- 已核验工件可「新增外链来源」，绑定当前工件 SHA-256。列表不回显原始下载 URL、查询参数、MinIO 凭据或服务器路径。
- 详情显示最近 10 个核验作业及错误码；窗口打开且有未完成作业时每 5 秒补拉，关闭窗口、离开页面或切换账号后取消请求与定时器。
- 核验通过后创建草稿，选择服务端允许的发布者/部署/渠道，填写普通或重要推荐级别以及纯文本更新说明（最多 30 条，每条 2000 字）。
- 发布前选择已核验且可用的自有 MinIO 或第三方来源，固定来源 ID/修订；最低支持版本码大于 1 并选择允许的在线能力时构成兼容门禁。始终保留本地数据和升级入口。
- 发布和停止操作提交当前策略修订与幂等键。相同表单的重试复用键；409/410 后禁止盲目重发，必须关闭、刷新、重新确认。
- 「停止分发」需填写原因，明确只停止新下载地址/安装许可；不能追回已公开文件或系统安装器操作。更高版本恢复使用「快速回退与恢复」。
- 「操作审计」显示操作者、原因、动作、结果、资源及前后策略修订。台账和来源均支持服务端游标分页。

新增后台专用扩展 `GET /aiyoloapi/admin/app-updates/configuration`：返回 `scopes`、`gateCapabilities`、`maxApkBytes`、`uploadEnabled`、`externalEnabled`。
范围与能力来自运维配置，不能由浏览器自行编造；功能开关表示已启用，具体存储/工具配置仍由请求和 worker 实际校验。
响应不包含密钥或下载地址，使用动态管理员鉴权、no-store 与同一读取限流预算；不接受查询字段。
工件详情 `details.jobs` 为后台可扩展投影，不改 App 签名授权载荷及共同金样。

## App 接口

- `check`：登录前可用，但必须匹配受控部署。每次返回新签名；无缓存 304。
- `download-ticket`：要求先完成该安装实例/当前版本的检查；核对当前策略、发布、工件及来源完整绑定。
- `install-permission`：重新核对上述绑定、设备版本、已核验文件码和批准证书，120 秒有效，必须用户操作且禁止离线安装。
- `receipts`：按实例/eventId 去重，attempt/sequence 不得复用；持久化客户端时间但只以接收和序列投影。

Check 包含包名、渠道、部署、SDK/ABI、签名和服务协议判断。
无兼容目标、来源不可用、未知客户端协议分别返回约定的非最新结果；不能用错误响应充当“已是最新”。
地址/许可不接受其他实例、摘要、大小、来源修订、旧策略或已停止发布。
所有签名绑定请求 ID/安装实例/当前版本和期限，使用冻结域分离及原始 JSON 字节。

### 双来源

外链返回已核验的 HTTPS 直链及域名白名单，URL 期限为空，签名授权期限仍有界。
检查、发地址和安装许可不重新完整下载外链，也不代理 APK。App 下载后必须自行核验文件。
托管方替换/删除公开文件仍可能发生；精确摘要和批准 APK 证书由 Android 拒绝错误字节。

MinIO 返回带固定 `versionId` 的预签名 HTTPS GET；先 stat 指定版本，核对大小和 ETag。
ETag 仅辅助对象状态检查，工件身份来自上传完整 SHA-256 核验。
同 key 后续 put 不影响已绑定 versionId；运维永久删除旧版本会使来源失效。
现有内部 HTTP MinIO 必须在正式使用前配置公开 HTTPS S3 网关或改用 HTTPS 存储端点。
`APP_APK_DOWNLOAD_ENDPOINT` 必须是无路径前缀、无凭据的 HTTPS origin，默认 443；使用它时 `MINIO_REGION` 必填，避免签名器为查询 region 访问公开网关。
网关必须保留签名 Host、原始 path、query、versionId，不能改写成业务文件代理；域名列入来源 `APP_APK_ALLOWED_HOSTS`。
后台与 App 不获得 MinIO secret；预签名查询参数不进入审计或列表。

## 状态、权限及资源边界

设备仅在 check/地址/许可/回执联系时入库；默认 not_discovered，不凭空推算未知设备数量。
discovered、downloading、downloaded、verified、waiting_install、installer_opened、started_pending_health、healthy、failed、canceled、superseded 分开记录。
打开系统安装器不记成功。迟到低序列和旧尝试事件留存但不覆盖当前投影；同尝试健康终态不能被后续下载阶段覆盖。
历史发布停止后仍允许补报该历史签名策略中已发布工件的事件。
last_contact_at 单独更新，成功只是客户端声明，不是可信硬件证明。

后台操作每次重新校验动态会话和当前启用 PLATFORM_ADMIN；拒绝普通、项目管理员、legacy token。
列表按 createdAt/ID 稳定游标分页，limit 1～100；不返回总量、原始外链、预签名查询、存储凭据和本地证据路径。
发布详情带当前策略修订及选定来源，供 T06 后台操作。
JSON 请求 64KiB/15 秒，拒绝重复键、未知字段、非严格类型和超限。
错误采用冻结 ErrorBody，不回显输入；响应 Cache-Control=no-store。
当前每进程 16 并发、每来源 IP 120 次/分钟，最多保留 4096 个 IP 桶，满时拒绝新桶；429 带 Retry-After。
反代部署需设置边缘限流；不信任任意 X-Forwarded-For。数据库持久实例/回执配额跨重启有效，达到上限需运维评估提升或后续治理，不能静默删审计。

## T08 安全与并发边界

所有管理写入口在读取请求体前校验动态账号会话，在完成请求解析后再次校验；请求携带的服务端会话摘要仅用于数据库事务内核对会话未撤销、未过期、所属账号一致，并锁定当前启用的平台管理员账号。摘要不进入 API、审计或作业记录。已接受的异步作业具有独立租约，后台再次核对账号权限；退出登录不会撤销已接受作业，停用或降权会阻止工件最终晋级。

发布、停止及回退以身份锁、策略 CAS 和事务提交为线性化点；会话撤销与写事务按数据库锁顺序串行，不能撤销已经提交的操作。幂等重放也重新校验会话和当前角色。上传完成补充 SQLite 写锁与来源类型校验，避免两个上传请求重复入队或跨来源复用幂等键。来源新增修订，既有工件摘要、版本槽位及来源定位不可通过管理接口原地改写。

入口预算分别为：发布/查询/移动元数据每进程 16 并发、每 IP 每分钟 120 次；MinIO 上传入口每进程 4 并发、每 IP 每分钟 30 次；外链登记两条路径共用每进程 4 并发、每 IP 每分钟 30 次。三类预算均最多 4096 个 IP 桶，429 返回 Retry-After，异常后释放并发名额。持久作业队列另按配置共享容量。此预算不跨进程共享，公开反代仍需设置连接、请求体、认证失败和全局限流。

外链 JSON 最大 16KiB/30 秒；拒绝重复键、深度异常、未知字段、查询参数和非严格类型。上传流有大小、总时限及单次接收时限；仅服务器 UUID 确定暂存路径。双来源响应及错误均 no-store，SQL 连接信息、请求值和异常文本不回显。清理仅针对终态作业；数据库短暂不可用时保留接收租约，恢复扫描标记失败并重试删除，清理失败保留 cleanup_pending。

审计保留操作者、原因、结果、请求摘要、策略前后修订、工件 ID 和来源 ID/修订；通过 API 拒绝的已解析发布/停止/回退请求另留 rejected 事件。未知身份、未解析请求、限流及数据库不可用由固定字段请求遥测记录，不把未认证输入写入业务审计。原因中的 URL、Bearer、PEM 私钥及常见凭据键值进行脱敏，原始原因仍被请求 SHA-256 绑定；运维不得在自由文本中填写密钥。核验证据在审计中仅存引用摘要，原始核验报告位于受限证据目录。管理审计投影不展开任意 details；退役来源投影为 failed，details.sourceState=retired，拒绝发布或签发许可。

外链逐跳验证 HTTPS、允许域名和全部 DNS 地址，TLS 连接固定已验证 IP 并验证原域名证书，不读取环境代理。重定向在 URL 拼接前拒绝控制字符、空白、反斜线和重复 Location；拒绝重复 Content-Length、TE/CL 冲突及非单一 chunked 编码。网络证据仅保存主机、已验证地址、状态和 URL 摘要，不含原始路径/查询或业务认证头。公开外链已交付的字节仍不可追回，Android 必须执行摘要、证书和安装前许可校验。

测试入口：`tests/test_app_update_security.py`。覆盖所有管理写路由动态身份、请求体接收期间撤销、事务内撤销/过期、上传失败清理、SQL 脱敏、预算释放、并发上传幂等、审计绑定和日志、恶意重定向及 DNS 重绑定；既有发布/回退并发、不可变对象和租约清理测试同时回归。真实公开部署和 Android 安装仍由 T09/T10 与 M118 验收。

## T09 本地真实联合验收

入口为 `tools/accept_m42_live.py`，必填 Android SDK build-tools、Java、android.jar 和 Chromium 路径。使用随机非 5432 端口的临时 PostgreSQL、随机 schema、真实 MinIO 的独立版本化测试桶、临时 APK 测试证书及独立 Ed25519 元数据密钥；不使用开发业务数据库，也不改写生产配置。

`admin-web/tests-e2e/app-updates-live.spec.ts` 通过真实 Cookie 登录和生产构建访问真实 API，不拦截或替换接口响应。完成真实签名 APK 的 MinIO 上传、HTTPS 外链与同包镜像登记、SDK 完整核验、发布、停止分发、无恢复包止损，以及 100 稳定→101 问题→102 恢复。MinIO 场景先绑定内部 102 来源，再登记外链镜像供外链场景绑定，避免两个渠道名称不同却都实际下载外链。项目负责人、项目用户均实际登录验证菜单及服务端 403。

`tests/test_app_update_live.py` 验证 check、下载授权、安装许可的 Ed25519 签名与请求绑定，分别直连 MinIO TLS 测试网关、第三方 TLS 源读取真实字节，核对大小和 SHA-256。外链下载前后业务 HTTP 请求数和 MinIO 网关请求数不变，仅第三方源增加 GET；无业务 Cookie 或 Authorization 到达第三方源。普通升级 100→101 与双来源 102 恢复均经过下载及许可，不以打开安装器或发出许可计为健康成功。

两个真实平台管理员同时发布同一草稿，要求恰好一个 200、一个策略修订冲突 409，只有一条成功审计；发布、停止和回退重放验证幂等。故障包括 403/404/429/503、HTML、错包名及同地址文件替换。另在队列未处理时重建 HTTP 服务、worker 和数据库连接池，确认已持久化任务继续完成，再验证已登录第二管理员降权后被拒绝。此项验证进程内组件重启，不覆盖主机断电或跨主机灾备。

证据目录为 `harness/evidence/M42/T09-<UTC>-live/`：浏览器日志、HTTP 方法/路径/状态、数据库投影、源站访问、MinIO 固定版本读取、服务断言、1440/390px 截图及桶删除记录。失败日志和 trace 保留。核验报告保留 SDK 输出和公钥指纹；临时私钥随临时目录清理。测试结束核对 schema 清理、测试桶删除与数据库监听端口关闭。

这些 APK 是 SDK 生成的资源型测试包，恢复兼容证据明确为测试 fixture。TLS 源使用测试连接工厂将已验证公网 fixture 地址映射到回环 TLS；MinIO 测试网关校验 SigV4 后通过 SDK 读取真实存储的指定 versionId。它们不证明生产域名或透明 S3 网关已部署，也不证明正式 App 数据迁移、覆盖安装及真机行为。正式签名、公网配置和 Android 历史数据保护仍由 M118/M42-T10 验收。
