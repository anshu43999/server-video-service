# 项目模型与项目场景管理界面

类型：当前领域界面目标说明；项目模型、场景与运行边界以 `PRODUCT_REQUIREMENTS.md` FR-13 为准。

历史实现：M36-T05。当前契约见 `project-model-assignments.md`、`project-scenes.md`、`project-scene-suite-v2.md` 与 `model-signing-publish.md`。

## 项目模型

项目模型页展示当前项目可用的精确模型版本清单，分为 PC 与移动端目标视图，每个目标端允许多个模型。列表不按平台模型的 `scenario` 标签或项目业务场景分组。每项清楚展示模型名称、版本、目标端、发布/产物就绪、启用状态及操作。平台模型选择只把模型加入项目清单，不创建场景成员，不启动检测。

分配只允许选择对应目标端已发布且产物就绪的精确版本。停用或移除项目模型会检查场景/运行依赖并要求显式处理，不会静默修改场景方案。

## 平台模型资产

平台模型目录明确显示 PC 端模型、移动端模型或 PC / 移动双端，并分别展示 PC、移动端的产物与发布状态。移动签名只对声明支持移动端的模型适用。业务模型可按精确版本选择目标端发布；PC 发布不要求移动转换或移动签名，移动端仍须通过自己的产物、许可证和签名门禁。

上传 PT 时必须选择仅 PC、仅移动端或双端。默认仅 PC；双端通过重复 `supportedTargets` 查询参数提交。上传完成只表示进入验证队列，移动端转换仍是独立动作。PC-only 验证任务不显示“生成移动端模型”，不会被强制进入 Android 转换。

## 项目场景

识别场景入口属于当前项目。负责人按 `project.scenes.manage` 创建、编辑、启停和维护有序模型成员，按 `project.scenes.approve` 批准或撤销；普通项目用户只读取服务端允许的已批准场景。前端能力只控制显示与交互，后端仍是授权边界。

列表采用紧凑表格，每行展示场景名称与标识、状态、输入能力、模型数、方案数，以及按权限显示的编辑、启停和批准/撤销批准操作。“详情”打开完整成员、运行方案、逐成员获准参数及低频管理操作；软删除仍需影响预览与二次确认。长名称在列表省略，悬停或打开详情可看完整名称；窄屏仅表格内部横向滚动，右侧操作列固定可达。详情始终从当前列表取最新场景，不缓存上一次打开的对象。

场景保存名称、输入适用性、成员及显式运行方案。成员只能从当前项目已分配且启用的模型清单中选择；详情显示精确版本和目标端。一个项目模型可被多个场景复用。图片/视频是输入能力标签，不作为场景身份。成员写入与编辑使用服务端 revision 做 CAS；409 或网络结果不确定时保留草稿并锁定重复保存，关闭对话框、刷新服务端状态后才能继续。

项目模型分配、场景方案和实际运行是分开的操作。编辑/批准场景不会自动绑定到流或启动任务；视频流/巡检运行必须由操作者明确选择 sceneId 与 planId。界面展示配置、审批和运行授权状态，不能把“已分配模型”显示为“已加入场景”或“正在运行”。

## 失败与可达性

PC 与移动端分别管理多条项目模型清单项；模型双端发布能力只决定可分配目标端，不把两个目标端呈现为业务场景。场景成员使用清单项选择器，不在场景编辑时隐式创建项目模型授权。

场景页覆盖加载、空列表、无权限、服务端失败、校验错误、并发冲突和成功反馈。对话框支持键盘 Enter / Escape，成员调整和移除按钮有可访问名称。桌面与 390px 窄屏沿用既有绿色工业管理台、Element Plus 适配组件和项目级导航，没有引入另一套视觉体系。

## 联合方案与参数审批（M36-T18，2026-10-21）

套件成员可以同时包含图片及本机相机连续帧模型。每个运行方案显式选择成员及 single/sync/async；图片方案不能选择仅支持视频的成员，反之亦然。方案只引用成员，不复制模型产物。

状态按真实含义展示：停用、待批准或待核验均为“已配置”；已批准且逐成员核验通过的多模型/sync/async方案显示“已配置 · 客户端未支持”，不暗示手机已经交付执行能力；合格的单成员 single 方案显示“可使用 · 需在线预检”，仍须在线 resolve。后台不执行推理，“同步”只表示同批次结果语义，不承诺物理并行。v3 配置解析须同时声明 `clientContractVersion=3` 和匹配的 `supportedExecutionModes`，旧客户端仍被拒绝。

场景详情的成员清单提供“配置待审参数”。编辑使用精确 `sceneId/memberId/sceneRevision` 定位到项目模型清单项和目标端；读取要求 `project.scenes.manage`，保存还要求 `project.models.assign`。保存使用参数 `expectedRevision` 做 CAS，并在项目事务锁内复查账号、项目状态、项目模型分配、成员关系、场景修订和模型可用性。

M29-T22 起，待审参数按项目、场景、稳定成员及精确模型版本/目标端隔离，不再编辑项目共享档案。首次读取以成员现有快照（未审批时以项目模型冻结快照）为基础；保存使用参数与场景双修订 CAS，递增场景 revision 并撤销审批，旧授权、下载、参数和 resolve 链接立即失效。重新批准后，将独立参数冻结到该成员及其方案来源。其他场景和独立项目模型不受影响；同一场景内复用该成员的方案共享成员参数。显式同步到新的项目模型参数修订会清除旧成员覆盖，应重新核对后配置。前端只提交白名单参数，不回传派生身份和下载地址。

每个类别只有“启用识别与告警”一个开关；关闭后不画框、不计数、不跟踪、不告警。启用仍遵守图片/相机告警阈值，不代表立刻生成告警。类别选择属于运行参数，不修改模型权重、Manifest 标签顺序或文件哈希。

本次证据见 `evidence/M36/M36-T18-validation.md`：浏览器验收使用隔离业务 fixture（1440px/390px）；另以独立 PostgreSQL 和真实 HTTP 验证两项目、三角色及已授权内部测试模型副本。没有改动开发实例、Default Project 或额外发布模型；Android 多模型运行及真实推理不是本任务的验收结论。

## 云端移除与影响确认（M112-T02）

场景页新增“删除场景”：先读取影响预览和 revision，明确勾选二次确认后再提交软删除。提示不级联删除成员模型、不远程擦除 App 文件；离线设备状态未知。停用是可编辑状态，软删除是不可复活的身份终态，不能借重新启用绕过。

平台模型页“卸载”先列分配、未退役场景/方案、流和活动版本计数；有依赖时禁用确认并要求先显式调整。停用/未批准场景依然阻止模型卸载。只操作精确版本，显示未共享产物物理回收与软停用的差别。共享文件和历史告警不随删除移除。

成功提示分别列实际回收、原缺失及保留共享文件数；`cleanupFailures` 非空时显示警示“版本已退役、文件清理待恢复”，不得显示全部回收。结果不确定时保留同一幂等键；409 关闭旧预览并要求重新预览。服务端仍重验权限、revision 和依赖，前端 checkbox 不构成授权。

沿用既有绿色工业管理台及组件，没有独立视觉体系；1440px/390px 浏览器回归及截图见 `harness/evidence/M112/T02/`。该回归使用真实隔离业务 handler、Cookie 和合成测试资产，不代表真实模型推理、生产部署或 Android 生命周期验收通过。
