# 独立告警持久化与通知契约（M34-T05）

日期：2026-10-15。遵守 ADR-003；不恢复 PC 推流、移动直播、检测帧订阅或媒体分发。

## 生产与持久化

`StreamSession` 的分析任务不由 PC 预览人数或通知订阅人数驱动。满足项目模型参数中的置信度、连续帧、停留时间和冷却条件后，`ServerAlertRuntime` 先保存证据，再登记正式事件，最后调度通知。检测结果本身不是告警。事件保留 `projectId`、`eventId`、`origin=SERVER_STREAM`、`streamId/sourceId`、规则修订和阈值快照。

- 证据/事件提交失败不提前通知；在同一进程后续帧重试时保持同一事件标识。证据写入先于数据库提交，失败后可能留下没有事件引用的证据文件，本任务不清理业务文件。
- 事件结束入库成功后才释放活动事件状态并开始冷却，失败可继续重试。
- 重启从持久事件恢复活动和冷却状态；人工 ACK 不是检测对象消失，仍在持续的已确认事件不重新生成一条告警。
- 模型缺失或推理失败不把检测缺失当作真实告警；沿用流诊断中的安全错误信息，不输出数据库连接信息或凭据。

## 通道与补取

| 用途 | 路径 |
| --- | --- |
| 正式事件列表/补取 | `GET /aiyoloapi/projects/{projectId}/alerts` |
| PC 站内通知 | `WS /aiyoloapi/projects/{projectId}/alerts/ws` |
| 已连接移动客户端站内通知 | `WS /aiyoloapi/projects/{projectId}/alerts/notifications` |
| 受保护证据 | `GET /aiyoloapi/projects/{projectId}/alerts/{eventId}/evidence` |

WS 消息为 `{ "type": "alert", "event": { ...正式事件... } }`。WS 是有界、非持久的加速通知通道，不是消息队列，也不是手机 App 关闭后的系统推送。没有订阅者或发生丢包时，已经入库的事件仍通过 REST 查询。`delivered` 回执表示适配器已接受发送，不代表用户已读或手机收到了系统通知；邮件、短信、企业 IM 的现有本地适配器也不等于真实供应商接入。

PC 当前项目使用一个全局告警同步器：首次 REST 建立历史基线；连接建立/恢复时补取，另每 5 秒补取一次以覆盖丢包或投递失败。首次载入历史不逐条弹通知，新正式事件按当前项目 `eventId` 在内存去重，重放可更新事件但不重复提示，也不能把已处置状态改回 OPEN。慢列表响应不能覆盖请求期间收到的新事件。提示复用 Element Plus 通知样式，独立于视频页面，仅指向告警处置语义，不提供直播链接。

首次列表失败时，新的正式 WS 告警仍可提示；不能把心跳、检测帧或测试投递探针插入正式告警列表。告警数据不写入浏览器持久缓存。

## 故障与撤权

- 适配器失败仍按既有有界重试处理，失败回执不回滚正式告警；REST 补取是站内数据恢复路径。数据库回执失败单独重试，不重新发送已经成功的通知；耗尽后进程内诊断保留 `receipt_persistence_failure`，并不能假称该回执已经写库。
- 分布式网络不存在由本实现保证的恰好一次送达，客户端必须按服务实例/账号/项目/事件身份去重。进程内投递任务没有持久 outbox，不能宣称服务崩溃后自动补发所有外部通知。
- 告警 WS 每次发送前重新校验账号/会话/项目成员权限，空闲连接每秒复验；成员撤销、账号/会话失效以及项目停用/归档后停止发送并关闭。连接关闭清理订阅队列，不继续后台等待。
- 项目切换、会话变化、离开页面或整机断网仍遵守已有项目安全门禁，清空可见数据、通知与连接。整机断网恢复后需要重新验证并选择项目；历史事件补取展示但不重复弹出。只有通知连接中断而项目仍获验证时，才自动重连、补取并提示新事件。
- PC 新预览仍要求当前项目权限及同源 Cookie；移动 Bearer 会话不能借告警来源 ID 获取 PC 预览。移动端只使用告警/证据/处置接口，退役视频路径继续拒绝。

## 验收边界

本任务验证服务端生产处理器、隔离 SQLite/JPEG、PC/移动告警接口与 PC 构建产物。浏览器的测试告警由仅存在于测试服务中的夹具登记，不冒充真实 YOLO。Android 产品页面改造及去重消费由 M101 负责，真实摄像机、YOLO、PostgreSQL、PC/API27 和长稳由 M34-T06 联合验收。未完成这些本地验收之前不进行容器部署。
