# 项目模型授权清单

平台模型资产与项目可用模型是两个边界：平台管理员维护模型版本、发布状态、目标端产物、签名和生命周期；项目负责人为当前项目选择可用的精确模型版本；项目成员只能读取其项目获准的模型。项目模型授权不是业务场景，也不代表模型已经启动。

## 项目模型

项目模型是项目级清单项，身份为稳定 `projectModelId`，唯一对应 `(projectId, modelId, version, target)`。同一项目的 PC 端和移动端均可授权多个模型版本；同一逻辑模型版本可在两个目标端分别授权。清单不包含 `scenario` 或场景分组字段。模型只有在目标端发布、对应产物就绪且操作者具备项目授权能力时才能分配。

项目模型记录精确版本、目标端、启用状态、参数来源/修订和 assignment revision。参数编辑不会隐式改变已批准快照；场景/方案批准时固定其实际使用的参数快照。移除或停用被场景方案引用的项目模型必须先显式修订相关场景，不能悄悄改写方案。

项目模型目录只返回当前项目已分配的精确版本，不返回同一模型族的其他版本。跨项目或未授权模型不可读取或下载；所有下载仍复核项目成员、目标端发布状态、产物完整性和 SHA-256。平台模型上传、发布、撤回、卸载和全局迁移仍要求平台模型治理 capability，项目负责人不能操作全局资产。

## 参数与并发

PostgreSQL/SQLite 持久化项目模型清单、参数草稿/快照和 revision。项目行锁、模型清单项 revision 与事务内权限复核共同保证首次分配、启停、移除及并发 CAS 不覆盖更新。失败事务不产生成功审计。项目暂停、归档或成员撤权会阻止后续读取、下载和运行授权。

## 接口约束

- 项目模型列表按 `target=pc|mobile` 过滤；每个目标端可以返回多条精确版本记录。
- 分配、启停和移除操作以 `projectModelId` 或精确 `(modelId, version, target)` 标识资源，并要求 expected revision；请求不能指定业务场景。
- 项目场景成员必须引用当前项目模型清单项；同一个项目模型可被多个场景复用。
- 流/巡检运行以显式 `sceneId + planId` 选择运行配置，不直接绑定单个项目模型。

## 测试阶段数据边界

本项目模型/场景重构不迁移旧的 scenario 型项目模型分配记录，不提供旧接口、字段或场景投影兼容。测试数据库按新 schema 和新 fixture 建立；不得自动清空或改写 Default Project、运行中服务数据库或部署实例。后续任何测试库重建都必须显式指定隔离数据库。
